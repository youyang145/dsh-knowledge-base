## 二十一、查库判定与资料入库（P2b / P3 的库内核）

**`src/consult.mjs`（P3 内核）**

- `shouldConsult`：闲聊/空查询/纯符号跳过，技术问题才查；
- `indexSummary`：分区 + 条数 + 每区前两条标题，当 AI 的"目录"；
- `consult`：判定 → 摘要 → 命中简介（含反例警示）；
- 整句 FTS 不命中时拆词兜底（二元组 + 拉丁词逐个 LIKE），GG 那句原本 0 命中，现在命中 3 条；
- CLI：`kb consult "问题" [--limit N]`。

**`src/ingest.mjs`（P2b 算法半边）**

- 分块：有标题按 `#` 切（不跨标题合并），没标题按段落并，单块上限 1200 字；
- 猜分区：块内词项撞各分区已有内容，给前 3 个候选与分数；
- 只出计划：写到 `_ingest/plan-*.json`，`chosen` 留空，人不点头不落盘；
- 入库：`chosen` > `--domain` > 候选≥0.15 > **待分区**；
- CLI：`kb ingest <文件> --title T`；`kb ingest --apply <计划>`。

**踩到的两个坑**

- `parseArgs` 会把 `--apply` 后面的参数当成它的值，所以 `--apply` 后面直接跟路径时要兼容处理；
- `segments()` 把拉丁词标成 `kind='word'`，不是 `'latin'`，拆词兜底一开始漏掉了英文。

**演示**：三块阴影笔记入库，全部落 `待分区`（候选分太低），符合"收件箱"设计。

## 二十四、插件外壳 MVP（第一次装进宿主）

- 位置：`dsh插件本地知识库/plugin-mvp/`
- `package.json` 带 `dsh.bundle.patch`，`cordis.patch.yml` 插入 `id: local-kb` 一行，配置 `home` 与 `code` 两个路径；
- `index.mjs` 只做一个工具 `kb_consult`：判要不要查 → 索引摘要 → 命中简介 → 反例警示；
- **不依赖 `@deepseek-ai/dsh-tools`**：工具描述直接用注册表认的 JSON Schema 形状，避免三方插件在真实 profile 里因缺 peer 而 import 失败（官方 defineTool 只是加校验，不影响注册）；
- 写入不开放：AI 只能查，不能改库，避免它自己往库里塞东西。

**验证**

- `node harness.mjs`：假 ctx 注册出 1 个工具；技术问题命中 3 条，闲聊返回"不查库"；
- 临时 `DSH_HOME` 下真实安装成功（pnpm 需要 `--store-dir` 指到可写目录）；
- `dsh --profile web --dump-config` 里能看到 `id: local-kb` 与两个配置项。

**已知限制**

- 还没有 client 半端，面板仍是独立 7788 服务；
- 只读不写；
- 插件依赖 `code` 路径指向本机 `dsh-kb/src`，发布前得把库代码打包进来或改成依赖。

**下一步迭代**

1. 真实 profile 安装一次（需要写 `AppData`，当前沙箱拒绝）；
2. 每轮自动注入索引摘要（系统提示或 turn 钩子），而不是等模型想起来调；
3. 加写入工具（`kb_ingest` 先出计划，`kb_add` 需人确认）。

## 二十五、插件迭代 1：三个工具（v0.2.0）

| 工具 | 行为 | 写库 |
|---|---|---|
| `kb_consult` | 判要不要查 → 索引摘要 → 命中简介 → 反例 | 不写 |
| `kb_index` | 只回分区目录（分区 + 条数 + 两条标题） | 不写 |
| `kb_stage` | 材料分块进「待分区」，附候选，最多 5 块 | **只写收件箱** |

**为什么这样切**：AI 最该被允许的动作是"递材料"，不是"改主库"。`kb_stage` 写进 `待分区`，人再挪，和共判是同一套权力划分。

**验证**（`node harness.mjs`）：

- 注册出 3 个工具；
- 查库命中 2 条、闲聊跳过、目录正常；
- 临时库里 stage 三块，`blocks/待分区/knowledge/` 下确实出现 3 个 `.md`。

**仍未做**：每轮自动注入（要宿主钩子）、`kb_add`（可直接写正式分区，暂不开放）。
